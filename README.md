# LCT
This package implements a Local Control Theory (LCT) driven molecular dynamics workflow for optical-field-controlled nonadiabatic simulations. It currently supports two common control scenarios: IR (vibrational control) and UV (electronic-state control). 
## Features

### LCT-driven dynamics workflows for IR (vibrational control) and UV (electronic-state control)

### Interactive setup script to generate input files and folder structures

### Automatic creation of trajectory directories for ensemble simulations

### Clear separation between setup/preparation and dynamics execution

### Compatible with external tools for initial condition generation and topology preparation

## Directory Structure

A typical project directory generated by this package looks like:

LCT_IR/                     # or LCT_UV/ (user-defined)
├── lct.in                  # main simulation input
├── paths.in                # path configuration
├── submit.sh               # job submission script
├── output_data             # ou
├── TRAJ_0001/              # trajectory folders
├── TRAJ_0002/
├── ...
└── TRAJ_0200/

Supporting input/model directories (provided or prepared by the user):

Initconds/                  # initial conditions and topology files
├── initconds               # generated by SHARC (Wigner sampling)
├── topol.dat               # generated by topology builder
├── initdb_dict_*.pth       # generated from SchNarc DB
└── ...

Model/
├── PES/
└── Dipole/

Each TRAJ_xxxx directory corresponds to one independent trajectory.

## Quick Start (Recommended)

The recommended workflow is:

### Prepare input data (initial conditions + topology + database-derived .pth)

### Run the interactive setup script to generate lct.in, paths.cfg, submission script, and trajectory folders

### Submit/run dynamics using the generated script

python lct_setup.py
bash submit.sh

## Interactive Setup Script

The setup script is:

lct_setup.py (renamed from make_lct_inputs.py)

It will:

1. Ask you to choose the control scenario (vibrational control and electronic-state control)

2. Ask for simulation parameters

3. Generate lct.in and paths.in

4. Create the main output directory and TRAJ_xxxx subfolders

5. Generate a submit.sh template using the correct runner script for IR/UV

## Input Files Explanation

### lct.in

The main simulation control file.

Common parameters:

natoms : number of atoms

ntraj : number of trajectories

nbead : number of beads

nstates : number of electronic states

dt_fs : time step (fs)

nsteps : number of propagation steps

scale_factor : field scaling factor

lct : control scenario (IR or UV)

IR-only parameters (vibrational control):

actstate : active electronic state

id_react : reactive/vibrational mode index

These IR-only parameters are not present in UV mode.

### paths.in

Defines file system locations required by the simulation:

initconds_path : directory containing initial conditions and related files

topology_file : topology database file (.pth)

topol_file : bond/angle/dihedral definition (topol.dat)

pes_model_root : PES model directory

dipole_model_dir : dipole model directory

savedir : main output directory (where TRAJ_xxxx folders will be created)

## Preparing Required Files

Before running lct_setup.py, you should prepare the following:

### Generate initial conditions (initconds) using SHARC

Use SHARC’s Wigner sampling script wigner.py to generate the initconds file containing initial geometries and velocities.

Example command:

$SHARC/wigner.py -n 200 freq.molden

-n 200 specifies the number of initial conditions to generate

freq.molden is the frequency file calculated by quantum chemistry software

Output example:

initconds

### Generate topology file (topol.dat) using ORCA-based workflow

A topology file (bonds/angles/dihedrals) is required by the dynamics code.

You mentioned you already have:

run_orca.py (script written by you) to generate topology-related output, which can be converted into topol.dat.

✅ You want to integrate this step into lct_setup.py.
At README level, we document it as a required preparation step:

Output example:

topol.dat

### Build the .pth topology database from SchNarc DB

You have:

make_pthfile.ipynb

This notebook uses SchNarc DB files to generate a .pth configuration/database file that the code loads as topology_file.

Output example:

initdb_dict_200.pth

## Running the Simulation

The IR and UV workflows use different runner scripts.

IR mode (vibrational control)

python run_dynamics_IR.py


UV mode (electronic-state control)

python run_dynamics_UV.py


lct_setup.py generates submit.sh with the correct runner by mode.

## Notes for Developers

The IR/UV separation reflects different control requirements (vibrational vs electronic-state control).

Setup and file preparation are intended to be modular:

SHARC generates initial conditions (initconds)

ORCA-based workflow generates topology (topol.dat)

SchNarc DB workflow generates .pth configuration (initdb_dict_*.pth)

lct_setup.py is the recommended place to integrate automated preparation steps (e.g., running run_orca.py).
